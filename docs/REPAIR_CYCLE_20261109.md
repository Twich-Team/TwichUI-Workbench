# Permission to repair and evidence of correctness

The owner's course correction removes model-generated executable checking artifacts
as a prerequisite for the first addon edit. Approved source/write scope, a clean
baseline, confinement, and a fresh normal Run approval permit an isolated attempt.
Implementation and native regression assertions develop together. Correctness still
requires new assertions failing against original production, passing with the frozen
candidate, the complete candidate suite, and independent acceptance review.

A settled failed scoped repair may continue through a normal fresh Run decision.
The app proves terminal failed execution, complete usage, revoked old grants,
restoration, dead run owner, no publication/checked/active/uncertain work, unchanged
provider/scope, and an exact allowed partial tree. The browser decision binds that
unfinished work and the prior history. It is frozen privately, then copied only
into a fresh granted isolated workspace. Old requests are not replayed or rewritten.
Unknown consequential activity is not covered by read-only quarantine policy.

Whole edit batches are previewed against the original base and existing write,
line, test-preservation and output bounds before any write. Ordinary constraint
feedback permits revision within the same operation; unchanged rejected edits stop.
Private durable journals restore an interrupted known batch or hold unexplained
contents. Provider lifecycle and usage receipts survive local output rejection.

Evidence and implementation status belong in CONTINUATION/CURRENT_STATUS and the
local deployment records. These changes do not establish completed task delivery,
real-provider acceptance, in-game behavior, publication or broader product completion.
