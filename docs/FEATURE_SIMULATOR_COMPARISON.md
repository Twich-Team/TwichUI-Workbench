# Feature simulator comparison

The fixed notification-appearance scenario captures a clean original addon and its
checked combined source. It opens the real settings page, navigates to text size,
sets UI scale to one, and advances a manual clock from zero by two seconds. Both
sides use the same simulator, pinned Forever UI, synthetic solo state, empty saved
variables, viewport and interaction sequence. No game installation is mounted.

This is structural evidence. Fonts fall back to Friz Quadrata, game artwork may be
absent, and the Forever simulator UI differs from the current client. Messaging,
combat, taint, secure actions, reload persistence and real-client acceptance are
not established. The two prefix-registration stand-ins are isolated lab support;
production addon files remain unchanged.

`scripts/capture_feature_simulator.py` is the native operator entry point. It needs
the installation-bound database/preparation environment, an exact checked combined
execution ID, and a private, byte-verified copy of the existing pinned simulator
profile. It validates the full checked source ancestry before executing anything.
It has no model, approval, publication or browser upload path. It rejects unrelated
source scenarios, links and oversized source archives. Each side runs offline with
120 seconds, 4 GiB memory, two CPU cores and 128 tasks. Native input, command, exit,
image and diagnostic receipts are retained. Existing or interrupted captures are
never overwritten or automatically replayed.

Passive PNG/log/JSON files live under the existing preparation owner's
`feature-context/simulator-comparisons` namespace. They bind the execution, result,
candidate, exact original/combined revisions and common conditions. The existing
context transfer preserves them across installations. Source staging and simulator
caches stay in private scratch, outside passive context and the checked run's
resource allocation. Results serves only validated passive images and metadata.
Changing a file or its binding makes the comparison unavailable; it cannot change
the original verification, model accounting, approval or publishing decision.

There is one fixed supported scenario, not a general model-programmed renderer.
Unsupported scenarios retain an explanation and offer no fabricated pictures.
An actual isolated map probe found missing MapCanvas APIs and absent map artwork;
the map feature cannot currently receive reliable map comparison evidence.

The November 12 controlled demonstration uses private original commit
`1caf530212bbc6eaf37e41d668902a391aa936c1` and non-model control
`1fed8db6bda07fe1ad9555f24c9582f58becf7eb`, changing only notification text-size
default 100 to 120 in a private clone. Real images and observed control values were
captured, inspected and retained privately. This is not the real map feature, an
accepted addon change, or a completed Feature Workshop lifecycle. Browser layout
tests use separately labelled controlled image data; they do not run the simulator.

Generated concept images remain a future provider integration. The app has no
authorized image-generation service or billing configuration and does not fabricate
generated artwork. Original owner images remain explicit plan references.
