## What changed

The existing real_execution grant/request/fence owner selects native-agent-v1
only for a new explicitly authorized task. Missing engine version retains legacy
behavior. The adapter uses existing intake/scope/backlog records, model_attempts,
provider_admission, real_handoff and checked-draft publication. There is no new
scheduler, execution ledger, migration or historical-task conversion.

Trusted owner ingress freezes the new report, historical link, Git base, exact
source disclosure, final writable scope/operations, Smart strategy, resource
limits and instruction digest. It records the actual owner instruction; it does
not manufacture a browser approval or change an earlier approval. Public original
input retains the existing strict schema and shows the frozen AI settings.

The native author gets a clean independent Git repository containing only approved
blobs. Before dispatch the worker and connector independently require its original
inventory. Native tools may write ordinary disposable source/scratch files, run
tests and revise. Protected Git/client directories remain read-only. There is no
mandatory model-generated checking program or individual-file runtime write policy.

The existing private connector authenticates the pinned Codex CLI separately.
Hooks, plugins, MCP/app discovery, web and delegation are disabled. Tool processes
cannot read credentials/host data or use network. The controller's sanitized
credentials/configuration remain outside the tool namespace. Publication credentials
never enter native execution. Signed-in ChatGPT mode and included-only account
checks remain mandatory; no API key or paid fallback is introduced.

Existing serialized Smart admission takes fresh supported observations and retains
waiting/fallback timing in the existing pending request. A native CLI session is
one admitted operation and may contain multiple model calls. Request-start policy
can overrun its cutoff while that operation finishes; strict ceilings hold instead
of claiming an enforceable token/percentage bound. Unreported model-call counts and
actual server model/effort remain unknown. Native reported input/output/cache and
reasoning counts retain their native meaning; reasoning is included in output.

The controller uses one recorded, bounded service cgroup. Input/output streaming,
watchdogs, original-authentication checks and whole-descendant settlement precede
export. Unknown dispatch cannot replay. Restart uses existing execution recovery;
uncertain provider reservations remain held. The scanner checks all entries,
including ignored/untracked files, metadata and empty directories. It rejects
unapproved changes, links, special files, unsafe modes and resource violations.
The gallery contract permits modification of its existing Python test only.

Independent verification receives a fresh full original tree with the accepted
bytes applied, not the dirty native workspace. Frozen source stays read-only.
The trusted verifier never imports the candidate into its own process. Candidate
tests run as separate bounded subprocesses; expected outcomes remain in the
parent's separate memory. Input mutation, unexpected exits, resource incidents
and incomplete inventories fail qualification. This separation closes an identified
same-interpreter interference risk; a hostile synthetic case proves the parent
cannot be changed by the candidate.

The gallery profile preserves the original Gallery class, shared helpers, artifact
paths and sample identities. It tests the corrected repository test against exact
valid outputs, all four recompressions, changed dimensions/R/G/B/alpha, absent
alpha, malformed PNGs, all eight TGA changes and exact manifest/ArtData changes.
It separately exercises retained catalogue and image-quality negative cases, and
the original test's compression-only rejection. The complete committed Lua/Python
inventory runs afterward. The existing completion/publisher owners bind the exact
candidate, checks, usage, destination and one canonical draft-delivery record.
